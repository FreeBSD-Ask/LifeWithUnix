# 4.1 UNIX 手册

> “月圆之夜行为古怪。”——4.2BSD UNIX 手册中 catman 的 BUGS 一节

## 4.1.1 简史

从很多方面说，UNIX 手册就是 UNIX 系统本身的一面镜子。手册最初由 UNIX 的实现者（而不是文档团队）撰写，因此只包含适合 UNIX 系统程序员的内容。最要命的问题是：它往往默认你已经通晓系统的其他所有部分。

比如，各种工具并不解释模式匹配的用法——那是 shell 免费提供的功能。可新手可能会因此以为，工具不接受经过模式匹配的参数，因为那一页手册上压根没提。

好处是手册极其精炼：用最少的字，把系统的每一部分说得清清楚楚。看这些作者写手册，仿佛和设计 UNIX 用的是同一套风格感。他们对自家程序的一些毛病，也颇有幽默感。

UNIX 手册的风格可以清楚地追溯到 Ken Thompson 和 Dennis Ritchie 的《UNIX Programmer’s Manual, Sixth Edition》（贝尔电话实验室，1975 年）。它大约 300 页，一卷装得舒舒服服，用 troff 排版，还带一份每一条目的轮排索引。第 7 版则是三卷：第一卷是扩充了 100 页的第六版手册；另两卷是文集，每篇都详细讲述系统的一个侧面。文档总量由此增加到约 1,200 页。（其实这些文集在第 7 版之前就存在，作为贝尔实验室的内部备忘录或计算机科学技术报告，只是从未和手册装订在一起。）

文集中有 Brian Kernighan 的《Introduction to UNIX》，短小却优美地介绍了 UNIX 的力量与简洁；还有一篇由 Kernighan 和 Ritchie 合写、标题就叫“UNIX Programming”的文章，用另一段简短的篇幅讲透了 UNIX 系统编程的全部哲学，例子清晰。Robert Morris 和 Ken Thompson 的《Password Security: A Case History》是另一篇文集文章，展示了开发者对自家系统缺陷那种开放坦诚的态度。在当时，想从商业厂商那里拿到这种信息，纯属做梦。

还有许许多多别的文章——全都短小精悍，读起来出奇地轻松好懂。此外，还有 troff、ed 等若干应用的教程。

这些写得极好的文档很早就存在，这无疑是许多人觉得 UNIX 平易近人的原因。

UNIX 传到伯克利后，文档再度扩编，部分原因就是又添了一卷文集。此时，UNIX 手册和 UNIX 系统一样，为了讨所有人欢心，开始臃肿起来。

更何况，UNIX 的用户不再只是那些能随手拿到源码或找到大师的系统黑客，而是普通凡人——他们想要完整的答案，想要没有计算机学位也看得懂的讲解。

尽管如此，如今的 UNIX 手册有很大一部分和最初面目时的样子相比并没有实质变化。我们认为这主要得归功于前面赞不绝口的原始风格。事实上，你能买到的最便宜的 UNIX 许可根本不含任何文档（文档大概在你本地图书馆里有），它早就由好几家出版社出版过。许多厂商只提供代码，外加一些关于软件差异和硬件特性的补充说明。

## 4.1.2 获取手册

UNIX 手册通常随系统而来。由于大多数 UNIX 厂商会对 AT&T 分发的系统做修改，厂商的手册往往比 AT&T 的版本更贴近实际。

不过，你没有系统也可能想弄到手册，这是办得到的。比如你可能在写一个 UNIX 克隆，或者想写一个能移植到多个 UNIX 版本的程序——这两种情况下，你都可以向较大的 UNIX 销售商购买手册：

* AT&T 和普伦蒂斯-霍尔出售 System V 手册。
* 普伦蒂斯-霍尔出售 X/OPEN 规范。
* IEEE 出售 POSIX 规范。
* 微软公司出售 XENIX 手册。
* USENIX 出售伯克利 UNIX 手册。

## 4.1.3 手册的组织方式

手册的组织方式与最初撰写时基本一致。很少有 UNIX 转售商会重新整理或重写文档的主体部分——这堪称 Dennis 和 Ken 远见与风格的真切证明。

手册分两个层级。顶层分成八节：

| 节 | 说明 |
| -- | ---- |
| 1. 命令与程序 | 用户级程序与命令。 |
| 2. 系统调用 | 系统调用，即内核直接支持的函数。 |
| 3. 库 | 子程序与子程序库。 |
| 4. 设备 | 设备与设备驱动程序。 |
| 5. 文件格式 | 系统文件的格式，如 **/etc/passwd**、**/etc/group**。 |
| 6. 游戏 | 全书最重要的一节。 |
| 7. 杂项 | troff 宏、ASCII 表及其他杂项。 |
| 8. 系统维护 | 对系统管理员有用的程序与文档。 |

你想找的信息属于哪一节，未必一目了然；就算知道在哪一节，你也未必确定该看哪个条目。手册开头的轮排索引是件特别有用的工具：它把手册中每个条目的标题按标题里的每一个词列出。所以，想了解读写磁带的命令，就查“tape”一词，能找到 tar、cpio、dump 等等。当然，哪个更合你的需要，还得逐个条目去读。

手册页通常叫“man page”，得名于同名命令——它把手册页打印到你的终端上。每页分为若干小标题，最常见的有 NAME、SYNOPSIS 和 DESCRIPTION。SYNOPSIS 通常是命令的一行式用法示例；如果你用过这个命令，这一行往往就足以唤起记忆。需要更多帮助的话，紧随其后会有长得多的总体说明。

视条目而定，可能还会有 BUGS（说明已知问题）和 FILES（列出命令用到的文件）之类的标题。

下面是一个虚构的国际象棋程序的手册页示例：

```
YACHESS(6)               游戏                YACHESS(6)

NAME
     yachess —— 国际象棋游戏

SYNOPSIS
     yachess [-w] [-b] [#]

DESCRIPTION
     yachess 是又一个会下国际象棋的计算机程序。用鼠标选中棋子，再移到
     新位置即可走棋。

     可选参数如下：

     -w   玩家执白。
     -b   玩家执黑。
     #    让计算机按这个等级分下棋。

DIAGNOSTICS
     “Illegal move” 就是字面意思。

SEE ALSO
     endgame(6), othello(6), chess(6)

FILES
     /usr/games/lib/chess.open      标准开局库
     /usr/games/lib/chess.cheaters  所有作弊者的记录

BUGS
     没有鼠标，这个游戏跑不起来。

Life With UNIX 发行版 1.0                                     1
```

## 4.1.4 什么？！没有内核手册？

想写设备驱动程序、想修改 UNIX 内核的人会发现：内核级函数根本没有手册页。常见的设备驱动手册页讲的都是用户层，而不是内部实现。比如 spl() 是一个改变硬件优先级的内核级函数，几乎每个 UNIX 和类 UNIX 系统都有它，却找不到 spl() 的手册页。

最初，spl() 及其他内核函数唯一的文档就是源码本身。人们开玩笑说：“凡是要靠文档才能搞懂内核函数的人，大概就不该去用它。”

这种态度倒不是想摆精英架子，而是在说内核编程的难处：改动内核里的一处，很容易（而且往往确实会）牵动别处，所以你必须对内核的大部分相当熟悉。既然你不得不把整个内核读一遍，那么内核级函数干什么用，也就自然知道了。

当然，这套说法实在被我们推到了极端。写设备驱动并不需要弄懂内核的一切；而且有些东西，光看代码是看不出来的。可这传统就是挥之不去，结果是很少有内核得到良好的文档。有些厂商把自家内核的文档做得不错，另一些则要你买下完整内核源码才给文档。如果你打算搞内核编程或写设备驱动程序，务必先确认能从 UNIX 供应商那里拿到文档。

讲设备驱动和内核级编程的书只有寥寥几本，其中特别好的一本是 Maurice Bach 的《UNIX 操作系统设计》（The Design of the UNIX Operating System）。它不针对某个具体实现，而是讲清原理、备选方案，并配了大量描述 UNIX 内核的代码。唯一讲伯克利内核的书，是 Samuel Leffler 等人的《The Design of the 4.3BSD UNIX Operating System》。

厂商也出过一些不错的设备驱动编写指南，但都针对自家系统，不通用。比如 Sun 有《Writing Device Drivers for the Sun Workstation》，我们也见过 Masscomp、微软和 SCO 出的类似好文档。此外，《UNIXWORLD》在 1988 年 1 月至 3 月连载了 George Pajari 的三篇《编写设备驱动程序》。最近，我们还看到一家厂商在自家手册的“第 9 章”里给内核函数做了文档。只能希望这种做法能传开。

不管你的系统是哪种，上面提到的两本书任选其一，配上厂商文档，就是学习 UNIX 内核编程的最佳组合。

作为补充读物，我们还推荐 Andrew Tanenbaum 的《操作系统：设计及实现》（Operating Systems: Design and Implementation）和 Douglas Comer 的《操作系统设计：Xinu 方法》（Operating System Design: The XINU Approach）。两本书都附有与商业 UNIX 系统非常相似的完整系统源码。

> **man 宏**
>
> man 宏是一组 troff 宏，提供统一的视觉格式，大大简化手册页的制作。干主要活儿的只有两个宏：.TH（标题行）和 .SH（节标题）。文本写好后，把新的手册页装到正确的目录里（通常在 **/usr/man** 或 **/usr/local/man** 下），man 命令就能找到它，你也将因为写出了这个了不起的、有文档的程序而名声大噪。如果你是出于别的目的创建手册页、不打算装进 man 命令查找的目录，可以用 `nroff -man 文件名` 来排版它。附注：制作新手册页最好的办法，是找现成的手册页来改。

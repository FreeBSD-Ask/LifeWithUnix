# 4.2 源码至高无上

> `/* you are not expected to understand this */`——UNIX V6 内核源码

最好的文档就是 UNIX 源码。毕竟，系统决定下一步做什么的时候，用的“文档”就是它！手册只是对源码的转述，而且往往与代码出自不同时期、不同人之手。把它们当成指南就好——有时它们更像一厢情愿。当然，有时它们也分毫不差，准确地描述程序，正确地指出限制、bug 和变通办法。

尽管如此，翻开源码却发现手册里没写的选项和行为，实在太平常了；有时又会看到手册里描述、源码中却没实现、直接被忽略的选项。

最初，UNIX 源码随每套系统提供。程序员可以同时参照源码和手册页——一边是真相（源码），一边是有用的提示和一厢情愿（手册）。可惜时代变了：大多数 UNIX 用户拿不到系统源码；就算拿到了，很大一部分人也看不懂——要么不懂 C，要么不熟悉系统的各个组成部分。

尽管如此，查阅源码仍然是理解 UNIX（乃至任何软件）局部细节的无价工具，只不过 UNIX 源码格外唾手可得罢了。真正的 UNIX 源码受商业秘密法保护；但即便有这些限制，想瞄上一眼也不算难。

大多数大学和许多非营利组织都有廉价源码许可。签一份保密协议（可能还要注册一门课），你就能读到任何 UNIX 源码。当然，你不许再分发，也不许用于商业获利。相比之下，想看到其他任何商业操作系统的源码——哪怕在课堂上——都极其不可能。

许多已出版的书描述 UNIX 程序和算法，大段摘录并详细讲解 UNIX 代码。此外，还有许多免费或低价的 UNIX 克隆实现（见地下世界一章），其中包含大量有用的源码。

本章稍后会较完整地介绍这些书，但这里必须提一下 John Lions 的两本书：《A Commentary on the UNIX Operating System》（一本是源码，另一本是评注）。它们收录了 PDP-11/40 上 V6 UNIX 的源码，并逐行解释代码。这两本书最初是在 AT&T 资助下为操作系统课程写的，可惜如今已不再出版。AT&T 坚决反对出版其专有代码，所以你再也不会找到任何收录真实 UNIX 源码的书了——有没有详尽讲解都一样。

虽然再没有别的 UNIX 系统注释源码集，但 Maurice Bach 的《Design of the UNIX Operating System》（本章后有书评）写得更好，对 UNIX 内核概念和算法的总体呈现也更完整。另外，地下世界一章里还有更多关于类 UNIX 系统的书和源码发行版的信息。

如果你运气好，手上有一台带源码的真 UNIX 系统，你会发现它们住在 **/usr/src** 目录里。这个目录下还有若干子目录。以下结构取自 4.2BSD，别的系统可能略有不同。

* **cmd**：命令的源码。比如 **/usr/src/cmd/ls.c** 就是目录列表程序 ls 的源码。有些程序因为源码文件较多（最好还有个 Makefile），会住在自己的目录里，比如 yacc 的源码就在 **/usr/src/cmd/yacc** 目录下。
* **games**：游戏源码。它们出现在 cmd 里也不稀奇，但常常单独放，这样磁盘空间紧张时可以一删了之。
* **libc 与 lib**：C 语言的库与支持例程。这些目录下还有以下子目录：
  * **crt**：C RunTime，含有特殊的运行时支持例程，比如性能剖析版，或加速版数学、字符串例程。这些通常用汇编写成。
  * **csu**：C Startup，含有所有 C 例程的入口和出口。你的 C 程序执行时，控制权先交给其中某个模块定义的入口，由它把 stdio、内存等设置好，再调用你的 main。
  * **sys**：用户级系统调用的源码。这些往往只是包装层：选好参数，调用一个通用的系统入口。真正干活（在内核里）的源码在 **/usr/src/sys**。
  * **stdio**：标准 I/O 库（所以叫“stdio”）及依赖它的其他可移植 C 库例程的源码。比如 fopen() 和 fprintf() 就在这里。
  * **gen**：手册第 3 节里构成可移植 C 库的大多数库例程。比如 getlogin() 和 malloc()。
  * **local**：本地开发、通常不随系统分发的源码住在这里。由于 **/usr/src** 一般放在一块未必总挂载的独立磁盘上，许多站点喜欢把本地源码放到 **/usr/local/src**，因为 **/usr/local** 总是挂着的。
  * **new 与 old**：分别存放命令和库例程的新版与旧版。有了源码控制系统之后，已经很少有人用这两个目录了。对于小程序，惯例是把旧源码和二进制改个名（比如改成 oyacc）留在原目录。做好心理准备：你会看到这些做法同时出现，够你晕的。
  * **sys**：若干用于生成 UNIX 内核的目录。最重要的目录叫 sys（没错，于是路径成了 **/usr/src/sys/sys**），里面有所有系统调用的系统入口。

读源码时，头文件至关重要。这些文件包含全系统使用的许多定义和数据结构，而且头文件本身往往就带有大量文档——比如数据结构的字段及其合法取值，在这里被记录的可能性比在使用它们的源码里大得多。

`#include` 文件可以在 **/usr/include** 里找到。比如 **/usr/include/stdio.h** 就在那儿，当 C 程序里出现

```c
#include <stdio.h>
```

这一行时，用的就是它。（尖括号的意思是“去 **/usr/include** 找这个文件”。）**/usr/include** 下还有存放头文件的子目录，最有名的一个叫 sys，里面是对 UNIX 内核重要的头文件。

我们可不希望你得出错误的印象。对手册保持合理的不信任是健康的，但也不必对白纸黑字疑神疑鬼。只有手册失职的时候，才需要去源码里搞清楚程序怎么工作。不过，很多人确实觉得，在一台没有完整源码的机器上日子很难过。

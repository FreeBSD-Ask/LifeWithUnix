# 12.10 并行处理

> “llooggiinn::”

由于门延迟、导线长度有限和电信号传播等物理原因，CPU 性能预计会达到一个极限，无论用什么技术都无法突破。我们最快的计算机，其硬件性能已经逼近这个极限一个数量级以内。要超越它，就必须同时使用多个处理单元——这就是并行处理的基础。

并行处理可以发生在系统的许多层次上。硬件的最低层相当常见：比如总线通常为每个地址位和数据位配备独立的线路，让它们能同时活跃。往上走一层，CPU 把取指、译码和执行流水化，至少由三个独立处理器并行工作，也很常见。

有多个执行单元的机器能做到更丰富的并行。这一层通常是软件能控制的最低层，因而也是 UNIX 设计者和程序员最先关注的层次。当然，最先关心这类硬件的软件，就是内核。

UNIX 内核最初并不是为并行处理写的。虽然设备驱动程序与 CPU 并行工作，但它们不像 CPU 那样可以在内存中随意漫游。为支持多处理器而必须对内核做的修改，通常是为只有主 CPU 访问的数据结构提供某种保护。比如，多个协作的处理器可能共享就绪进程队列：一个处理器干完一项任务，就取下一个就绪进程。其想法是，如果有比如 100 个进程、三个处理器，就能用单个处理器所需时间的三分之一跑完；再加一个处理器，就变成四分之一。现实中共享访问公共数据结构会有一些开销，但相比用户处理时间，这可能微乎其微。采用这种技术的系统有 Encore、Elxsi 和 Sequent。

某些硬件在用户控制下显式提供并行。一种有限形式是：必须生成代码去访问 CPU 外设，比如专用浮点芯片；一种可能的做法是用不同的数学库调用 C 编译器，数学库再像访问外设一样访问浮点芯片。

更精巧的形式出现在 Multiflow Computer 公司的 VLIW（超长指令字）技术中。VLIW 编译器生成的指令控制大量专用逻辑单元，使许多操作能在单个周期内完成。这种情况下，编译器实际上在用户层面提供了并行，而无需用户操心。（这或许可以看作把水平微码用到了极致。）

经典的流水线技术出现在 Cray-2 这类超级计算机上。这里的并行发生在用户层面。虽然用户不必直接控制它，但为并行执行设计的算法在这种环境里会有显著提升。反过来，BBN Butterfly、Intel Hypercube 这类系统展现的更灵活通信，则要求对算法设计格外用心，否则根本看不出提升。

这方面好的参考文献有 Omri Serlin 在《UNIXWORLD》上从 1986 年 1 月起连载的《Parallel Processing》系列文章，评述了 UNIX 机器上各种类型的并行处理。其他生产并行计算机的 UNIX 公司包括 Alliant Computer Systems 公司、Arete Systems 公司、Concurrent Computer 公司、Elxsi、Encore Computer 公司、EnMasse Computer 公司、Flexible Computer 公司、Masscomp、Sequent Computer Systems 公司。

# 12.11 实时处理与 UNIX 执行体

> “我现在就要。”——Elizabeth Ressler（四岁时）

实时计算指的是计算机系统在已知时间段内触发并响应外部事件的能力。比如，控制机械臂的计算机可能得每秒提供 100 次新的关节位置，才能产生平滑的运动。

UNIX 当初是作为分时系统开发的，几乎没顾上响应时间。大多数 UNIX 系统里，处理响应和延迟问题的工具都非常粗糙。

比如，在 BSD 4.2 和 System III 之前，根本没法让系统把进程挂起不足一秒的间隔；即便你要求睡眠若干秒，系统也不保证进程何时恢复——它会说：“……由于系统中的其他活动，可能再任意延长一段时间。”

针对这些问题的变通办法变得很普遍，可惜各站点做法不同。忙等待是多数用户最简单的方案，尽管它同样给不出任何保证。另一种办法是造一个 I/O 设备：从它读取 n 个字节，除了花 n 毫秒之外什么也不做。这有个好处——响应更好，因为驱动（运行在内核里）一做完就能重新调度进程；但仍无保证，因为别的进程仍可能以更高优先级执行。

更糟的是，系统调用执行期间，进程可能被换出到磁盘；也没法把进程或进程的某些页面锁定在内存里。

除了定时，UNIX 支持实时处理还有别的长期问题。比如调度很粗糙：nice 系统调用能给调度器一些提示，但方式非常有限。大多数系统不支持连续创建文件以获得最优磁盘访问，不支持锁定内存页，也无法以其他方式与换页器沟通。许多系统访问共享资源时的信号与同步机制不可靠，或者过于复杂、昂贵。

从 System III 和 4.2BSD 开始，较新的 UNIX 版本通过增加系统调用，支持更精细的控制。这些系统仍不保证响应时间，却大幅提高了按时响应的可能性，其响应能力已足以实现实时任务。更好的是从一开始就为实时响应设计的 UNIX 系统。你可能看到某个像 UNIX 的系统，但别奇怪这些实时 UNIX 系统其实完全重写了内核。提供实时 UNIX 系统的公司有 Alcyon、AT&T、Gould、惠普（Spectrum）、霍尼韦尔、IBM（AIX/VRM）、Integrated Solutions（UniWorks）、MassComp（RTU）、Modcomp（REALIX）和摩托罗拉（cXV/RT）。

由于 UNIX 一直缺乏实时设施，许多公司围绕全新的内核提供类 UNIX 系统。预计 1989 年之后实时 UNIX 扩展会标准化，因此把目光投向非 AT&T 系的 UNIX 仿制品完全合理。提供这类实时类 UNIX 系统的公司有 Action Instruments（IC-DOS）、Charles River Data Systems（UNOS）、Technical Systems Consultants（UniFLEX）。

另一种生成快速 UNIX 系统的选择是 UNIX 执行体（executive）。执行体是轻装上阵的操作系统，没有文件系统、shell 和全部用户级程序这些包袱。这同样是个尚未标准化的领域，但这类系统通常用于控制器：在最小 UNIX 内核的控制下运行一组协作应用。

这类系统往往完全固化在 ROM 中（软盘都算奢侈品），上电即启动。适合运行在执行体下的应用，是那些不常变化、却又复杂、有实时要求的应用，比如网络网关、激光打印机和机器人控制器。

提供此类执行体的公司有 Emerge Systems（RTUX）、Eyring Research Institute（pDOS）、Industrial Programming 公司（MTOS）、JMI Software（C Executive）、Ready Systems（VRTX）和 Software Components Group（pSOS）。其中许多还带有交叉开发工具，如下载器、交叉编译器、交叉调试器和交叉汇编器。

关于实时 UNIX 的进一步信息，一篇极好的参考文献是 Wendy B. Rauch-Hindin 的《UNIX Overcomes Its Real-Time Limitations》（《UNIXWORLD》第 4 卷第 11 期，1987 年 11 月）。

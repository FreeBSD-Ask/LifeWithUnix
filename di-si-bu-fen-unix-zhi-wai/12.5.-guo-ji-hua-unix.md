# 12.5 国际化 UNIX

```sh
% grep /etc/passwd
```

**图 12-1　作者名字的汉字写法：唐李贝斯**

> **译注**：原书在 `% grep /etc/passwd` 这一示例行中嵌入了上面这个小图，用作者名字的汉字写法（唐李贝斯，即 Don Libes）演示字符集问题。

UNIX 是在美国由母语为英语的人开发的，这一点从 ASCII 深深嵌入系统就看得出来：UNIX 程序里写死了英语短语（如 No such file or directory），字符集也硬编码其中。

人们常拿非英语的 UNIX 命令名（如 grep、ls）开玩笑，说不带英语偏向；这话说岔了，因为结果只是让所有人都同样别扭！随着 UNIX 变得更友好，我们会看到不仅英语使用者、而是所有用户都觉得 UNIX 更好用。把英文错误信息译成其他语言，只是其中一小部分。

在解决使用其他语言的问题之前，UNIX 先要面对表示其他国家字符集的困难。大多数 UNIX 文本工具每个字节只用七位（以支持 ASCII）来操作字符；试图用满八位，往往会让许多工具意外失灵——比如 shell 和邮件程序，它们常把多余的那位挪作己用。所以，哪怕只增加几个字符都很难。那汉语这样的语言呢？它有超过 25,000 个字符，无法方便地用单字节表示。必须采用多字节表示，但这要求重写支持例程（如 ctype 宏、字符串子程序），往往还要重写应用。

有些语言的书写方向不同；视上下文而定，字符可能有大写形式，多个字符也可能映射为一个（如德语）。排序不再是简单比较字符表示——字母表未必按机器的表示顺序排列；有些字母表要求从字符串另一端开始排序，另一些则要参考周围单词的上下文。正则表达式解析对其他字母表中某些模式的匹配，可能不再像英语那样强大。

日期、时间和货币必须按当地惯例输出。比如，UNIX 一直懂时区概念，但有些时区会因所在国家不同而有多种名称；有些国家调整时钟的幅度小于一小时。

UNIX 的国际化需要大量研究与开发，但大型国际厂商在其他计算机系统上已经做了很多。X/OPEN 联合体及其他国际组织的成员，正朝着这些问题的解决方案大步前进。目前已有厂商销售面向其他语言的产品版本，如 System V 日语版。最终，UNIX 系统可能会带有极其灵活的语言支持，比如让用户更改任何消息。

关于 UNIX 在美国以外地区的使用与能力，见 1985 年 12 月号《UNIX REVIEW》，其中有多篇相关文章。另一篇值得一读的是 Jean Wood 与 Hans-Joachim Brede 的《Parlez-Vous L’UNIX? The European Perspective, Past and Future》（1985 年夏季 USENIX 会议录）。

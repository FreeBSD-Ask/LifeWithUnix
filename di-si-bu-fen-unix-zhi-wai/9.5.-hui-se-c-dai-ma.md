# 9.5 晦涩 C 代码

许多 C 程序员把自己的“信仰”看得很重。对这些 C 教条主义者来说，抵达涅槃的唯一途径就是研读 K&R，写出能在 PC 和 Cray 之间移植的程序，并且永远、永远不写 `#define BEGIN {` 这种行。

这固然让 C 程序员看起来像一群无趣的人，但幽默还是有的。日常的 C 幽默包括 `char broiled;` 和 `double trouble;` 之类。如果你发现同事一读你的程序就龇牙咧嘴，不妨考虑参加国际晦涩 C 代码大赛（International Obfuscated C Code Contest，IOCCC）。大赛每年由 Landon Noll 和 Larry Bassel 主持，为那些读起来难受得反而好笑的代码提供一个舞台。换个角度看，你甚至可以说它有教育意义。Landon 说：

> 大赛的灵感来自阅读某些 UNIX 源码（4.2BSD 的 **/etc/config**）。我震惊于糟糕的代码风格竟能把简单的算法弄得如此晦涩、如此无用。“会有人为这种代码感到骄傲吗？”

我们没法把所有获奖作品都复刻出来，挑几个就足以让你领会大意，也许还能促使你去找齐全部。每一件都保证够你研究好几个小时。它们不只告诉你别做什么，还教你如何对付极其古怪的代码；研究这些不寻常的程序，你还能学到 C 的一些精妙之处。与本书其余部分不同，我们遵循大赛精神，不对每个程序作任何解释。你自己琢磨吧。下面，开奖……

# 12.3 模拟器与共存

> “我挺好……你也挺好。”——Thomas Harris
>
> “我挺好……你是个讨人嫌。”——Albert Vorspan

好吧，我们承认——UNIX 不是世界上唯一的操作系统；我们也承认——UNIX 的版本多得我们不愿去想。剩下的问题是：当你需要在同一台机器上运行两套不同的操作系统时，会怎样？

这种局面可能因政治、经济或技术原因而出现。比如，你只买得起一台计算机，却想同时跑 UNIX 和别的东西。

这事能办到。显然，办法因情况而异，有些也不那么优雅。要把两套都想完全控制硬件的操作系统揉在一起，可能是个棘手问题。有时，你并不真的需要同时运行两套操作系统，而只需要它们两边的功能。

最简单的情形是同时运行两个不同版本的 UNIX。大多数命令在各版本间一模一样，但有些情况下程序、系统调用或库名会冲突（即名字相同，参数和功能却不同）。为缓解这个问题，用户通常指定一个默认使用的版本。有些系统允许逐条命令指定，有些则按会话指定。

这类系统的例子有 Altos（Xenix 与 System V），以及 Pyramid 和 Wollongong（System V 与 4.3BSD）。美国陆军弹道研究实验室（BRL）提供了一套公有领域的、在 4.2BSD 下运行 System V 的实现。

比在同一台机器上装两个 UNIX 版本更难的，是让 UNIX 与非 UNIX 操作系统共处。复杂的操作系统可以模拟足够多的 UNIX 系统调用，使 UNIX 应用无需修改就能运行。既然 UNIX 如此可移植，把内核中依赖机器的部分剥掉、在原生操作系统之上提供高效的 UNIX 系统调用模拟，并非不可能。例子有阿姆达尔公司跑在 VM 之上的 UTS，以及 Wollongong 集团跑在 VMS 之上的 Eunice。

然而，UNIX 本身虽可移植、不要求特定硬件环境，UNIX 式的编程方式却可能给原生操作系统带来古怪的麻烦。比如，一个 UNIX 进程在执行时 fork 出许多子进程并不罕见；而在进程创建代价高昂的操作系统上（如 VMS），这样的 UNIX 应用能把原生系统拖垮。

反过来说，许多专有操作系统是围绕其所运行的单一硬件专门设计的，往往比不利用专用硬件的 UNIX 更快。甚至可能出现（我们也确实见过）模拟的 UNIX 比原生 UNIX 还快的情况！

UNIX 模拟从来算不上无缝，却可以相当宜居。想想看：UNIX 是为程序员设计的，系统管理员只能捡剩下的。许多其他系统似乎把这个优先级倒了过来。因此，UNIX 跑在另一个操作系统之上，可以让程序员用 UNIX，而系统管理员用另一套完全不同（也更好）的工具来管理系统。

一些在其他系统之上提供 UNIX 的公司有：Data General（AOS/VS）、Convex、Interactive、HCR 与 Wollongong（DEC VMS）、IBM（VM）、Apollo（Domain）。

正如 UNIX 可以架在更复杂的操作系统之上，也有些系统简单到可以跑在 UNIX 之上。MS-DOS 就是个好例子。由于 DOS 相对简单（与 UNIX 相比），在 UNIX 之上为它提供支持很容易。早期的 DOS/UNIX 系统通过模拟 Intel 8088 汇编以及 BIOS 和 DOS 系统调用来工作。如今 PC 兼容板便宜得很，大多数厂商改为在 UNIX 背板上插一块 PC 板、当作协处理器来支持 DOS，结果是一个毫无瑕疵、跑得和真 DOS 系统一样快的 DOS 环境。

在 UNIX 下支持 MS-DOS 环境的厂商有 AT&T、ICON International 公司、Interactive Systems 公司、Locus Computing 公司、Microport Systems 公司、Prime Computer 公司、The Santa Cruz Operation、Sritek、Sun Microsystems 公司和 TeleVideo Systems 公司。

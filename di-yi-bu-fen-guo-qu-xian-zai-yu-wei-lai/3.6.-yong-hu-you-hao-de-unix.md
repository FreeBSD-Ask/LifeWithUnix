# 3.6 用户友好的 UNIX：Macintosh 与 Smalltalk 的影响

UNIX 要想活进下一个十年，它的用户界面就得动手术。从一开始，UNIX 就是为程序员、而不是为新手设计的，这一点至今没怎么变。虽然许多 UNIX 系统上有面向菜单的 shell、窗口系统和其他辅助手段，但要高效地使用 UNIX，UNIX 工具仍是不可或缺的一环。

而这正是它在如今这个讲究用户友好界面的时代里相形见绌的原因。跟苹果 Macintosh 的 Finder、施乐的 Smalltalk 浏览器这类漂亮前端比，UNIX 占不到便宜。而世界正朝着这种交互方式前进，这一点毫无疑问。

UNIX 围着管道和过滤器打转：把一个程序的输出喂给另一个程序，把一堆互不相识的程序钩在一起。

Macintosh 的模式恰恰相反。系统不处理字符流，数据文件层次极高，通常假定是为某个特定应用专有的。你上一次在 Mac 上把一个程序的输出用管道接给另一个程序是什么时候？（能找到管道符号就算你运气好。）程序都是铁板一块，好处是你能彻底搞明白自己在干什么——但你可不会把 MacFoo 和 MacBar 钩在一起。

毫无疑问，我们会看到 Mac 式前端实现在 UNIX 系统之上。事实上，跑着 A/UX（Apple 发布的 UNIX System V，带伯克利增强和 NFS）的 Mac II，在融合 UNIX 与 Macintosh 两个世界之长这件事上大有前途。我们已经等不及要拿鼠标一路 hypercard 过去，在文件系统里穿行，看看垃圾桶、磁带机和 shell 的图片。

Smalltalk 呈现的面向对象模型和 UNIX 的思路接近得多——尽管 UNIX 做得不如 Smalltalk 那么好（也没那么极端）。想想 UNIX 的 I/O 就是个好例子：你可以把数据写到磁盘、磁带或者飞盘上，具体活儿由各自的驱动程序去干，而 write() 在每种情况下用法都一样。

Smalltalk 的前端（“浏览器”）让人能在庞大陌生的环境里穿行。随着 UNIX 纳入越来越多的工具、界面，以及……呃，怎么说呢……破烂，任何人都越来越难掌握它，新手就更不用说了。UNIX 未来会摆出海量选项，在其中穿梭浏览——挑挑拣拣，决定看什么、用什么——将成为唯一的驾驭之道。

在那之前，我们只能将就着过现实里的沉闷日子。当我们拼出各种复杂得离谱的管道、shell 脚本和二十个进程的组合来实现一个拼写检查器时，我们还会继续梦想一种集音频、视频和通信于一体的个人计算图景——Alan Kay 的 Dynabook 把它描绘得淋漓尽致。†

> † Alan Kay 与 Adele Goldberg，《Personal Dynamic Media》，《IEEE Computer》，1977 年 3 月，第 31–41 页。

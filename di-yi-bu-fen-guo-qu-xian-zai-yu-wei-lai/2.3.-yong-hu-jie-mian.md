# 2.3 用户界面

大多数人用 UNIX 时，最先看到的就是它；而那些后来没有去做 UNIX 编程的人，往往就此认定 UNIX 无非就是它这个样子。（shell 的细节见讲用户环境的章节。）

其实，我们大多数人用的 shell 只是与系统交互的一种方式。你还可以用窗口系统、菜单系统，或者干脆自己设计一套界面。只不过因为多数人打交道的就是 shell，我们才把它看成 UNIX 的脸面。

shell 是为程序员用户设计的，不是为新手设计的。讽刺的是，大多数 UNIX（以及其他计算机）用户对编程压根没什么兴趣。几乎所有命令都需要一点创造力和编程思维。比如，要把日期打印到行式打印机上，得敲：

```sh
date | lpr
```

这条命令把两个现成的程序组合成一个新功能。shell 还支持复杂得多的表达式，以及用任何编程语言都能写出来的那种精巧程序。

反过来说，如此复杂的界面也自带把人淹没、令人困惑的复杂性的可能——就像任何一门语言一样。shell 不带保姆属性——UNIX 里本来就少有——所以说话得留神。

要证明 shell 对新手不友好太容易了。经典例子是 `rm *` 会悄无声息地删掉当前目录下的所有文件，不管你本意如何。（也许你只是想删掉一个名叫 * 的文件。）

这算特性还是算 bug，取决于你的立场。rm 根本看不见那个星号：是 shell 把星号替换成一串文件名，再交给 rm。要是 rm 知道你刚才请求的是删掉自己全部文件，它或许会问一句“确定吗”——毕竟这个请求相当不寻常。

尽管如此，这么做是有道理的；而且，你也有办法保护自己。我们不是要为 UNIX 的重大缺陷道歉，而是想说明：shell 是为那些对自己行为的后果有一定认识的程序员设计的。

毕竟，想象你在开车：你把方向盘一打，车头直冲一棵树。车子会问你“确定要朝树开吗”吗？不会。就算它真有这份智慧，你也可能有正当的理由冲向那棵树——或者超速 20 英里——甚至倒着开回家。

UNIX shell 刚问世时堪称一绝，当时没有能与之相比的东西。早期的 shell 以今天的眼光看当然原始，但要点在于：shell 始终是程序员的好工具。管道、重定向以及 shell 的控制特性，让程序员能很快写出新程序，常常一行 C 代码都不用写。小而近乎简陋的工具可以轻松组合，变成又一个能以同样方式使用和组合的工具。

没有文件格式之别，也没有文件与设备之分，用户和程序从此不必操心这些差异。一个程序一旦实现，它从设备读输入、从键盘前的用户读输入，还是读另一个进程的输出，都一样顺畅。

用户界面与其他工具合在一起，营造出一个具有协同效应的环境，让程序员的生产率远超其他系统。而他们的劳动成果，反过来又让其他程序员立刻就能看懂、拿来就用。

# 2.6 可移植性 第一幕

检验各版本异同的一个办法，是看应用程序的可移植性。如果你是某个基于 UNIX 的产品的最终用户，而厂商把同一产品在两个版本上都跑了，那你大可以不管这事；如果你是那个厂商，得让产品在刚才提到的那位用户那里跑起来，那你就得关心，写产品的时候也得多留个心眼。

各 UNIX 版本之间（包括 Berkeley、System V 和 XENIX）最要命的差异，都集中在 V7 从未涉及的领域，比如实时处理和网络。

此外，UNIX 系统在 V7 涉及过、但处理得不太够的地方也分了岔：进程间通信、虚拟内存、设备控制和信号。

因为这些差异，你不能想当然地认为用 C 写的 UNIX 代码就可移植。写可移植软件是一门需要大量经验的专门手艺，费钱又费时。可移植性这东西和 C 一样，不是为所有人准备的。

话虽如此，写出可移植的 UNIX 软件仍然可行。想学这门手艺，有一本特别好的读物：Rabbit Software 的《Portable C and UNIX System Programming》。照着它的准则做，程序通常能轻松移植到大多数像样的机器上。但也别离谱到抱怨你那台 1 KB 内存的 Sinclair ZX81 跑不了 troff。

当然，有时候就是得写不可移植的软件。那就至少做到两件事：明确对外说明它不可移植；并尽量把不可移植的部分隔离出来——这样有朝一日你的软件搬到新机器上时，可怜的程序员看到你的源码也不至于心脏病发作。

正在进行的标准化工作也许能减轻可移植性的麻烦，这些在讲未来的章节里有详细讨论。等到它们真的成为正式标准（而且我们大家选定了同一个），写“保证可移植”的代码或许会容易得多。

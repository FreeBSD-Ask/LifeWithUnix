# 1.5 政治 第一幕

UNIX 诞生之时，AT&T 是一堆通信相关公司的集合体，其中包括贝尔电话实验室（常被称作 BTL、Bell、Bell Labs 或“实验室”）和 Western Electric 公司（WECo）。由于早先一桩反垄断法庭裁决，AT&T 被禁止涉足某些不受管制的领域。它可以在 UNIX 上做研究，但绝无可能销售任何基于 UNIX 的产品。事实上，计算机软件是否被允许经营都说不清楚；但看情形，一旦有利可图（而当时看不出有什么希望），AT&T 就会撞上早先那份同意裁决书的红线。无论如何，UNIX 作为商业产品看起来都注定没戏。管理层自然不愿赞助一个没法上市的产品——1970 年代初，Ken、Dennis 和 UNIX 面对的就是这么个局面。

Dennis 和 Ken 在位于新泽西州 Murray Hill 的贝尔实验室工作，真正的 UNIX 研究在那里进行，他们并不怎么关心产品开发——摆弄自己刚出生的“孩子”实在太好玩了。可奇怪的是：这样一件在整个实验室里越来越受欢迎的东西，却不能对外分发；而且没有任何人负责对外支持 UNIX。按 Tannenbaum 的说法：†

在早期，BTL 其实没有什么分发政策。你收到一块磁盘，附一张便条：

> 这是你的 rk05。爱你，Dennis。

要是 UNIX 把你的 rk05 弄坏了，你就再写信向 Dennis 要一块。

> † Andy Tannenbaum，《UNIX 的政治》（Politics of UNIX），华盛顿特区 USENIX 会议，1984 年。

最终，贝尔顶不住分发 UNIX 的压力，制定了一套简单的许可政策：不提供支持，没有试用期，不作任何担保，不做宣传，不修 bug，先付款。

不过，贝尔内部使用 UNIX 的人实在太多了。为了支持这些项目，实验室成立了一个 UNIX 支持小组，即 USG（UNIX Support Group）。不幸的是，USG 获准只提供支持，不准做任何开发。结果是，无论实验室内外，用户都在自己搞开发——而 UNIX 随附的完整源码又进一步助长了这种风气。USG 发布过几个 UNIX 版本，大多只在实验室内部流通。

与此同时，PWB 正基于另一个 UNIX 版本兼做支持与开发，而且 PWB 可以在贝尔实验室内外分发。不用说，两个小组之间积怨不少：各自都认为自己在做正确的事，对方是错的。比如，PWB 的 shell 就和 USG 的 shell 不一样。

还有一个 UNIX 版本叫 MERT，即 Multi Environment Real-Time（多环境实时系统）。MERT 类似虚拟机的概念：UNIX（准确说是它的一个特别版本）可以跑在 MERT 之上，并利用 MERT 的部分实时能力。

在贝尔实验室之外，许多被许可方选择 PWB/UNIX 或 Ken 和 Dennis 的研究版本；而在实验室内部，用户们用 USG 的某个 UNIX、MERT，或者另外那两个。（其实版本还更多。例如 LSX 就是一套面向 LSI-11 微处理器的 UNIX 版本，约 1977 年问世。）UNIX 系统的名目繁多，已经相当让人头疼。

此时，许多 UNIX 被许可方已经在 PDP-11 上装了某个版本的 UNIX，或者把它移植到了别的硬件上。对大多数程序员来说，摆弄 UNIX 比摆弄替代品要痛快得多，原因在于：

1）UNIX 附带完整的源码和文档，能自给自足。你拥有和 UNIX 开发者一模一样的开发环境，可以亲自动手改造 UNIX。

2）UNIX 很小，代码读得懂，大多数算法都简单，你可以有把握地动手修改。

3）没有保修条款可以作废。系统既然不带支持，你就没什么可失去的：最坏也不过是翻出备份磁带；最好的情形，你能把系统调得更快，或者添个新特性。

4）UNIX 手册读得下去。统共也就几百页，通读一遍并不难，一个人轻松就能掌握全部内容。

当年 UNIX 活动的几个重镇是：

**Rand、哈佛与 BBN**

Rand 开发了第一套交互式分时系统，也很快看出了 UNIX 的价值。Rand 委托 BBN（Bolt Baranek & Newman 公司）的 Walt Bilofsky 开发 UNIX 上的第一个屏幕编辑器。这个被称为“Rand 编辑器”的东西，是 UNIX 上第一个屏幕编辑器，也成了实验室之外开发的最早几件“必备”程序之一：把 UNIX 跑起来之后，下一步就是装 Rand 编辑器，这被视为理所当然。（其实 Rand 编辑器自带一堆毛病，最要命的是它在 CPU 时间和通信带宽上是个可怕的资源饕餮。）

这种做法一直延续到今天：UNIX 一装好，人们立刻塞进一堆公有领域的工具（比如 GNU Emacs、RCS、Usenet），它们早已成为 UNIX 程序员的必需品。直到现在，人们对出厂状态的 UNIX 也还是不满意！

写 Rand 编辑器的时候，Rand 和 BBN 其实都没有 UNIX 系统。他们跑到有第四版的哈佛去借用机时，作为回报，哈佛可以使用 Rand 与 BBN 做的改进。后来哈佛自己也加了些东西，其中一部分又被并回了第五版。比如 Brent Byer 加入了指令/数据空间分离的支持，以适配拥有独立映射寄存器的 PDP-11/45。

BBN 继续承接合同工作，后来在伯克利的 UNIX 发展史上扮演了非常重要的角色。那时 BBN 已经参与过 Arpanet——美国国防部（DoD）开发的网络。BBN 运用自己的经验，让 UNIX 具备了使用 DoD 协议通信的能力。这些成果经过增强后被打包进伯克利的软件分发中。结果，使用伯克利 UNIX 的公司可以免费获得网际互联能力。UNIX 与网络的早期渊源由此开始。

**劳伦斯伯克利实验室——虚拟操作系统（VOS）与 Software Tools 项目**

在劳伦斯伯克利实验室，Dennis Hall、Deborah Scherrer 和 Joe Sventek 读了 Brian Kernighan 和 P. J. Plauger 的《Software Tools》，觉得这本书讲得非常有道理。他们实现了书中介绍的所有工具，包括一个 shell。令人惊讶之处在于：这一切是在一台根本不运行 UNIX 的机器上做出来的！

为了可移植，所有工具都用 Fortran 66 写成——那是当时大多数计算机上唯一可用的语言。可惜 Fortran 并不适合系统编程，Ratfor（“Rational Fortran”）随即诞生。Ratfor 试图给 Fortran 补上 C 的许多特性（比如更好的控制流结构），它的实现方式是一个预处理器：吃进 Ratfor 代码，吐出 Fortran 代码，后者可以用任何 Fortran 编译器编译。这样一来，任何人都能以极小的代价把 Software Tools 引导到自己的系统上。

没过多久，他们就把 Kernighan 和 Plauger 的工具移植到了好几种操作系统上。在这个过程中，他们搞清了哪些抽象在各机器间是通用的，哪些不是。1979 年，后来被称为 Software Tools 项目的团队与 USENIX（当时最大的技术导向 UNIX 用户组）联合举办了一次会议。其中的许多抽象与 UNIX 相似，很多人把 Software Tools 项目看作一个机会——让自己手上那些“不幸的”机器也能享受到 UNIX。

会议之后，工具又被移植到更多机器上，一份虚拟操作系统（VOS†）的规范随之成形。VOS 定义了一个逻辑层，Software Tools 就安放在这层之上：只要一台机器能支持 VOS，就能支持这些工具。虽然 VOS 的某些抽象在部分机器上很难实现，最终的成果却是一套出色的可移植开发环境——Software Tools。

这项成就的一个例子是：Software Tools 支持进程间的管道——尽管当时许多系统既无任何进程间通信，也不支持多进程。这是怎么做到的？工具用临时文件模拟管道，并发也不是必需的，靠程序串联来模拟。效果别无二致，用户最终获得的是和 UNIX 工具范式同样美妙的协同效应。

VOS 环境非常成功，至今仍在使用，把 UNIX 的好点子带到了几乎任何别的操作系统上。许多厂商已经把 VOS 的一部分并入了自家原生系统。VOS 的原始源码属于公有领域。

> † Hall、Scherrer 与 Sventek，《A Virtual Operating System》，《Communications of the ACM》第 23 卷第 9 期，1980 年 9 月。

**伯克利**

加州大学伯克利分校计算机科学系（人称“Berkeley”，偶尔也叫“Berserkeley”）很早就在 UNIX 上尝到了甜头，他们的许多成果也分发到了其他站点。1979 年前后，Ken 利用在实验室的休假在伯克利教操作系统课。逗留期间，他把 UNIX 移植到了一台 PDP-11/70——一台能支撑大量用户的强力机器。他的存在鼓舞了许多学生，他的工作也让更多人得以参与 UNIX 开发。

同一时期，DARPA（国防部高级研究计划局）正在为 AI、VLSI 和视觉研究寻找一个通用的计算环境，目的是省钱并减轻开发负担。UNIX 可扩展、体积小、移植性久经考验，是个不错的选择——但它缺网络、缺虚拟内存管理、也缺灵活的进程间通信。UNIX 的主要竞争者是 VMS，DEC 为自家 VAX 计算机开发的操作系统。VAX 被看作关键所在：它是第一台 32 位超级小型机，支持带虚拟内存的 VMS。

许多人对 DEC 很有好感——他们的 PDP-11 在研究界极受欢迎。不过 VMS 确有一些缺点，而且 DARPA 颇为担心：VMS 是专有产品，DEC 会响应他们的修改和改进请求吗？最终，他们决定选择 UNIX。

DARPA 开始物色 UNIX 开发项目的落脚点。除伯克利外，CMU 和 BBN 也被重点考虑。不过，伯克利的 Bill Joy 已经在改造 UNIX 内核，让它在 VAX 上支持分页。伯克利成了主要实现地点，同时一个由贝尔实验室、CMU、MIT、斯坦福和 BBN 代表组成的 DARPA 指导委员会监督着项目进展。所有这些机构的努力，对伯克利 UNIX 的设计都很重要。

贝尔同意让伯克利再分发其源码，前提是客户已持有贝尔的源码许可——具体地说，伯克利在分发中并入哪个系统，你就得为那个系统取得源码许可。所需的许可变过好几次，因为贝尔自己发布了一大批发行版，而伯克利在不同程度上都并入了。

起初伯克利并没有重写 UNIX，而是对一个叫 32V 的版本做了大量修改和增强。32V 是贝尔的研究人员把 UNIX 移植到 DEC 32 位 VAX 上的成果。为图省事，他们把 VAX 当作一台大号 PDP-11，无视硬件本该具备的能力——让程序寻址超过物理内存容量的内存，也就是虚拟内存。伯克利很快补上了这项能力，由此产生的系统叫 3BSD（1980 年又有 4BSD）。VAX 允许程序寻址 1 GB 内存，哪怕机器只有 1 MB 物理内存。

虚拟内存实在难以抗拒。既然 32V 不支持它，实验室之外的所有人（以及实验室内的多数人）都改跑伯克利的 UNIX。仅凭这一项优势，伯克利的扩展就声名远扬，并被视作 UNIX 的必备部分。尤其是 C shell、curses、termcap、vi 和作业控制，被反向移植回了第 7 版（以及后来的 System III），所以在本来很“纯”的贝尔发行版上看到这些东西并不稀奇。人们常说的“伯克利扩展”就指这些程序，比如“我们的系统跑的是 System III 加伯克利扩展”。较新的伯克利扩展（来自 4.2BSD）还包括网络（DARPA Internet）支持和内核自动配置。

伯克利给 UNIX 添了许多好东西，但有一件事他们无能为力：支持。大学不可能去做计算机生意、提供客户支持——这毕竟本该是个研究项目（花的是纳税人的钱）。就像 Dennis 那张关于 rk05 的“情书”一样，早期的伯克利磁带附有 Bill Joy 的建议：“这是一盘装着比特的磁带。”意思是概不担保任何东西，有意见请寄往 **/dev/null**。

实际上，伯克利的人对 bug 相当通情达理：他们维护一份可以通过电子邮件访问的 bug 列表，修掉了人们发现的许多问题，也把别人的补丁并入自己的代码。后来成立了一家公司来支持伯克利的发行版，名叫 Mt. Xinu。它的口号“We know UNIX forwards and backwards”（我们对 UNIX 了如指掌）是一句巧妙的双关：Mt. Xinu 正是 UNIX 的倒写。

伯克利的软件发行版一直顶着“4.X BSD”的标签，尽管各版本之间差异巨大。伯克利本想把 4.2 改标为“5.0”，可大学的规定会迫使它给所有“客户”重新发放许可。结果因为并入了一份新版 AT&T 软件中的代码，伯克利还是不得不重新许可了一遍。

AT&T 似乎也认准了“System V”这块招牌，哪怕它最近的几个版本差异巨大。AT&T 大概花了太多钱去宣传“UNIX System V。来自 AT&T。从今往后，就当它是标准”，改名字实在不划算。于是它改用“大版本发布”的办法（例如 UNIX System V Release 4.0）。

**Digital Equipment Corporation**

DEC（Digital Equipment Corporation）处境尴尬。所有最早的 UNIX 用户都在 DEC 硬件上跑 UNIX（也就是 PDP-11 和 VAX），可 DEC 不对 UNIX 提供任何支持。碰上某些类型的硬件故障，这就成了大问题：DEC 的诊断程序和 DEC 的操作系统往往跑得好好的，UNIX 却不行——你只能靠自己。

尽管如此，DEC 内部仍有人对 UNIX 感兴趣。而且显然，UNIX 已经无法在最终的损益表上被无视了。一方面，UNIX 让用户在选择软件和外设时获得了大得多的自由；DEC 的系统则强迫你使用专为 DEC 计算机和操作系统设计（通常也是 DEC 设计）的终端和软件。相比之下，UNIX 的限制少得多。

最后一击是 UNIX 被移植到了 DEC 之外的机器上。DEC 意识到：既然有了选择，用户就会去买那些愿意支持他们想跑的系统的厂商的机器。如今 DEC 已全面支持 UNIX（以 ULTRIX 之名销售），但它更希望用户选择自家的专有系统 VMS，从而锁死在它的硬件产品线上。然而，面对众多对 DEC 硬件感兴趣的 UNIX 用户，DEC 也不想把他们拒之门外。

1986 年，针对 DEC 的 VAX 硬件，大约有 6,000 份 DEC ULTRIX 许可、14,000 份伯克利 4.X BSD 许可和 20,000 份 AT&T System V 许可。此后，DEC 为自家大多数老机器和全部新机器都加上了 UNIX 支持。有意思的是，同一时期，AT&T 反而放弃了对 DEC 硬件的 UNIX 支持。

**其他**

除上面列出的之外，还有许多大学和研究机构为 UNIX 做出了重要的应用和扩展。它们分布在加拿大、澳大利亚、新西兰、欧洲和美国各地：有的发布自己的版本，有的把伯克利或 AT&T 的版本重新发布，顺手把自家增强和名头缀在原版后面；有的则偏离得足够远，已经不能算作 UNIX 了。名目之繁，实在铺天盖地。

许多贡献者没兴趣打理自己的发行工作，干脆把东西寄给伯克利（伯克利似乎来者不拒）。正因为如此，伯克利无意间揽下了许多本属于别处的功劳。

# 6.5 综合运用

读完本章，希望你已对 UNIX 用户界面的哲学有了像样的感觉，也记住了几条命令。为了把几个要点钉牢，同时让讨论更具体，本节给出一个由单个 shell 脚本构成的简单工具，用的是前面提过的那些命令。

有些命令还有我们没提到的选项（或参数）——选项用来改变命令的默认行为。想了解更多，请查阅 UNIX 手册。

我们的例子是一个执行管理任务的 shell 脚本，这个任务是 UNIX 本身没有提供的：归档用户。归档的意思是，把他们的文件备份到脱机存储（如磁带或软盘）上，然后从文件系统中删除。用户离开公司或学校时，通常都这么办；否则文件系统里会塞满早已离开的用户的文件。

我们的程序叫 remove-user，其实很简单：它只要 1）把目录复制到备份介质，2）删除该目录。不过，我们还会出于礼貌给用户留一封信，以防他们哪天再登录进来、纳闷自己的文件去哪了。

remove-user 是为 Bourne shell（sh）写的。好的风格是把第一行写成特殊注释 `#!/bin/sh`。（这样做的原因在程序员一章里讨论。）Bourne shell 的注释以 # 开头。

既然我们要删除文件，那么归档和每一步操作出错时进行检查就很重要。一个简单的办法是设置一个特殊标志，让脚本一遇到错误就停下：

```sh
set -e
```

我们还要确保只有系统管理员能运行这个程序。虽然普通用户删不了别人的文件，但超级用户如果不小心对自己运行了 remove-user，就可能删掉自己的文件。

```sh
if test -e $USER = root
then
        echo "Must be root to run remove-user"
        exit
fi
```

这个 if 语句展示了 shell 的高级语言特性。do 循环、for 循环、switch 以及其他控制结构也都有。大多数命令会返回一个布尔值，可供测试；这里我们只需拿一个 shell 变量（USER）和一个值作比较，所以不必动用外部程序。这类情况下，可以用 test 来计算任意表达式并产生布尔值。

remove-user 接受一个参数——用户名。有了用户名，就能在 **/etc/passwd** 里找到对应条目，从而算出该用户的目录。传给 shell 的第一个参数用 `$1` 取（第二个是 `$2`，依此类推）。我们可以用 grep 搜索口令文件：

```sh
grep "^$1" /etc/passwd
```

grep 返回整整一行，里面有一大堆我们用不着的信息；我们要的是第六个字段。用 awk 很容易把它挑出来。既然要让 grep 的输出成为 awk 的输入，就用管道把两者接起来：

```sh
grep "^$1" /etc/passwd | awk 'BEGIN {FS=":"} {print $6}'
```

我们不想把结果存进文件，而是要放进一个 shell 变量。最简单的办法是使用反引号机制——它用命令的输出来替换整条命令：

```sh
directory=`grep "^$1" /etc/passwd | awk 'BEGIN {FS=":"} {print $6}'`
```

结果就是，shell 变量 directory 里装上了该用户的目录名。现在可以用 tar 归档这个目录了。tar 的更多内容见管理员一章。

```sh
tar -c $directory
```

虽然我们假定这位用户已经人间蒸发，但留个消息总归不错，万一人家登录进来找文件呢。我们可以给他发邮件。好在邮件并不存在用户的目录里，而是存在邮件系统的私有目录中。这里我们用了另一种间接方式，让命令从脚本中紧随其后的几行读取输入：

```sh
mail $1 << EOF
Your files ($directory) have been archived and removed from the file system.
Please see an administrator if you need them back.
EOF
```

这些命令执行完，我们就知道用户的文件已经安全了，可以放心删掉在线的那一份：

```sh
rm -fr $directory
```

完整的 remove-user 脚本如下：

```sh
#!/bin/sh
# remove-user username

# 遇到任何错误即退出
set -e

# 确认我们是 root
if test -e `who am i` = root
then
        echo "Must be root to run remove-user"
        exit
fi

# 取得用户目录
directory=`grep "^$1" /etc/passwd | awk 'BEGIN {FS=":"} {print $6}'`

# 归档该目录
tar -c $directory

# 给用户发信，以防他忽然又冒出来
mail $1 << EOF
Your files ($directory) have been archived and removed from the file system.
Please see an administrator if you need them back.
EOF

# 删除该目录
rm -fr $directory
```

你可以做很多事来改进这个程序，但我们的本意只是用一个真实的 shell 脚本，演示本章讲过的一些东西。

重要的是结果——我们没费多大劲，就用简单的现成工具拼出了一个 shell 脚本。之所以容易，是因为这些工具好用，而且设计上就考虑到了彼此拼接。

用同样的工具还能搭出复杂得多的程序。如果你在程序设计中遵循同样的准则，你的程序也能被别人轻松使用和并入他们的程序。

许多使用 shell 的用户并不觉得自己是程序员，哪怕他们写出了很长的管道或 shell 脚本。然而，编程是使用 UNIX shell 不可分割的一部分。shell 编程也许没有 C 编程那么吓人，但结果一样强大。

这正是“UNIX 用户”和其他操作系统的用户之间最大的差别之一：在大多数别的操作系统上，想轻松扩展或修改用户界面是件苦差事；而 UNIX 用户不受设计者原始方案的束缚，会用一些谁都没梦想过的方式去使用系统的工具和命令。

# 8.4 管理终端与串行线路

人们常说，UNIX 里用来控制和定义终端、串行线路的程序太多，令人困惑：供人登录的端口与其他端口的控制方式不同；某些终端特性可能定义在内核里（用 stty），也可能定义在 shell 里（用环境参数）、用户程序里或库里。你说得对——确实乱。

## 8.4.1 init 与 getty

UNIX 管理终端和串行线路的方式与其他任何操作系统都不同。系统本身并不坐等用户登录，而是把登录用户的责任交给 init 进程，这就为内核本身卸下了一些复杂度。

init 具体怎么做，取决于你用的是什么系统，但基本思路如下：根据你的系统是伯克利系还是 System V 系，文件 **/etc/ttys** 或 **/etc/inittab** 会为系统上的每条串行线路保存一条描述。每条描述规定是否允许登录，以及线路的特性，如速率和奇偶校验。（其实特性存在另一个文件里，不过这无关紧要。）

如果某条串行线路设置成允许登录，init 就监视 RS232 控制线。控制线若表明有用户存在——比如检测到终端开机，或调制解调器被呼叫——init 就 fork 出一个 getty。（某些版本的 init 会为每一组 RS-232 控制线各 fork 一个 getty 来监视。这更简单，但更浪费资源。）

getty 打印出 `login:` 字符串（或你的站点定义的别的东西），把终端设置妥当，提示输入用户名；然后调用 login，由它核对口令、完成登录。login 的最后一步，是用 **/etc/passwd** 中为该用户定义的 shell 覆盖自身。

用户登出时，shell 返回到调用它的过程（即 init），init 随即回去监视串行线路。

> **Semicolon-login:?**
>
> 你大概猜到了，通讯 ;login: 的名字来自 UNIX 的登录提示符。可开头那个分号是怎么回事？
>
> 原来，getty 提示时输出的字符串，其实以一个转义序列加分号开头。这个序列让 Teletype Model 37 进入全双工模式；可大多数人不用那种终端，别的终端会忽略这个转义序列，打印出分号，再接上 login:。所以，从前大多数 UNIX 用户看到的提示总是 ;login:

这整套系统的好处是，它不必操心用户登录：一切由一个独立进程处理。而且，如果你所在的站点有特殊要求，比如要一个全系统口令或特殊环境变量，修改 login 程序也很容易。

恼人的是，UNIX 二进制许可是按固定用户数卖的；可操作系统本身没有任何机制阻止更多用户登录——你只需编辑相应文件。即便你的 VAR 重写了 login 程序来检查用户数，自己写一个允许任意人数的也并不难。

当然，我们不能纵容这样违反许可协议。不过，我们认为从技术角度你可能会感兴趣。比如，uucp 登录看起来就像一个用户，尽管根本没有人在场。因此，你甚至可能在一个单用户系统上看到两个“人”登录着。

## 8.4.2 termcap 与 terminfo

**/etc/termcap** 是一个描述终端能力的文件。每种终端（如 vt100、adm3、hp2621）都有一项，描述该终端的特性；这些特性由一个公共库（curses）读取，每个字符图形程序都用它。

只定义一次终端特性、并提供唯一的使用方式，避免了几个问题：

* 程序员不必为每种终端写代码，只需针对一种“虚拟”终端。
* 程序员不必操心最优的屏幕绘制过程，系统会自动完成。
* 用户不必担心新终端能否正确运行所有旧程序。

> **TERMCAP 环境变量**
>
> 屏幕编辑器这类程序启动时，需要知道终端特性。它先在 TERM 环境变量里查找你所用终端的类型。
>
> 再用这个终端类型，从 termcap 数据库取出终端特性。数据库很大时，这可能颇费时间。减少耗时的一个办法，是把你的终端特性放进名为 TERMCAP 的环境变量里（用 tset 很容易做到）。如果系统在 TERMCAP 里找到终端描述，就会采用它。结果是字符图形程序启动快得多。

termcap 数据库里的信息，包括光标定位、字符/行插入删除的字符序列，以及用于填充和优化的定时信息。终端厂商若随产品提供 termcap 描述就好了，可惜这么做的很少。不过写一份也不算太难。

termcap 在许多方面都是一件杰作。它好用到被应用到系统的许多部分（以及许多其他操作系统）：比如有描述打印机的能力文件（**/etc/printcap**），还有描述主机的文件（**/etc/remotes**），风格都与 **/etc/termcap** 相仿。结果是一个非常灵活的环境。

termcap 最初在伯克利写成，很快被 AT&T 用于自家系统；不过 AT&T 为 System V 重新设计了一部分，并把名字改成了 terminfo，还重组了终端能力数据库：不再把所有数据放进一个文件，而是把每种终端的特性放进若干目录之一里的单独文件。这比 **/etc/termcap** 高效，但系统的工作方式基本相同。还有几个公有领域程序可以在 termcap 条目和 terminfo 条目之间互转。

## 8.4.3 设置终端选项——stty

stty（set tty）用来告诉系统关于你终端的某些事情，比如可以用它改变波特率和流控。stty 有两个主要用途：一是出现在登录脚本里，让你登录时终端特性被正确设置；二是在某个程序不体面地退出后修复终端。比如，若某个程序把终端留在了原始模式，你可以敲 `stty sane`（System V）或 `stty -raw echo`（BSD），再按一下 control-J，终端就复位了。

若有权限，也可以设置其他终端的特性。注意，你不能对拨号线路用 stty，因为 init 会立刻按 **/etc/ttys** 或 **/etc/inittab** 里的描述把它们改回去。

stty 没有与 termcap 集成，这有点烦人。问题不在于它们做的两件不同的事，而在于 stty 管得太宽——它其实就是终端问题的原始大杂烩。termcap 的设计者无视它，做得对。

# 6.3 文件结构与命名

UNIX 文件系统是 **分层** 的。也就是说，它像一棵树（虽然通常画成倒过来的），有一个根，还有许多枝杈和叶子。下面是一个小型 UNIX 文件系统的图示：

```
/
├── bin
│   ├── ls
│   └── cat
├── etc
│   └── passwd
├── lib
│   ├── cpp
│   └── libc.a
├── usr
│   ├── don
│   │   ├── books
│   │   │   └── lwu
│   │   └── articles
│   ├── sandy
│   ├── lib
│   └── local
│       └── bin
└── dev
```

> **译注**：原书此处是一幅手绘的树状图，节点之间的连线表示目录包含关系。上图按原图结构用文本重画。

一个极小的 UNIX 文件系统。名字看起来直接对应文件（如图所示），但实际上，名字对应的是指向目录的链接。

文件系统的根永远写作斜杠（“/”）。因此，只要敲 `ls /`，就能列出树顶层的文件：

```sh
Yes, master? ls /
bin  dev  etc  lib  usr
```

包含其他文件的文件叫目录。其实 UNIX 对不同类型文件区分得很小：大多数操作文件的命令，无论面对的是文本文件、目录还是别的什么类型，都能照用。设备在文件系统里也表现为文件——这样你就能用操作文件的同一套命令来操作设备。

目录的有趣之处在于，它控制着对其他文件的访问——哪怕只是按名字访问。你可以“身处”某个目录之中，这时所有文件都相对于该目录访问。以示例文件系统为例：如果你在目录 / 下，看到的 lib 和在 usr 目录下看到的 lib 就不是同一个。“相对”意味着“相对于当前目录”，当前目录就是你所在的那个目录。

文件名前面可以带目录，用斜杠（“/”）分隔。所以，如果当前目录是 /，我们可以用文件名 `usr/lib` 指代第二个 lib。

绝对路径名总以斜杠开头，其实也只是相对于文件系统的根。无论你当前在哪个目录，像 **/usr/lib** 这样的文件名都指向文件系统中唯一的一个文件。

UNIX 系统规定：名为 `.` 的文件永远指当前目录，`..` 指父目录。这两个名字在很多场合都很有用。比如，你想切换到同一层级的另一个目录，比如 foo，可以用绝对路径名，也可以用简便得多的 `../foo`。

UNIX 文件系统的许多特性极受欢迎，已被其他操作系统照搬。不过有一个特性在其他操作系统中很罕见：文件名区分大小写。因此，文件名 foo 和 Foo 指的是不同文件。文件名里几乎可以用任何字符；但有些字符被 shell 挪作特殊用途（见下一段），用起来很别扭，也容易让读的人犯迷糊。比如，文件名里若有空格，“foo bar”就可能被看成两个文件。自己掂量着办。

利用正则表达式，用户可以用模式来指定一个文件名或一组文件名，而不必逐个拼写。正则表达式是某些模式的理论分类——你不必懂理论，但它的威力极其强大。

为了实现正则表达式，shell 保留了一些字符。比如，字符串 foo 匹配文件名 foo，而 `f*o` 能匹配 foo、fooo、foooo，还能匹配 fao 和 fhelloo——因为 * 被定义为匹配任意字符串。

方括号用来匹配一组字符（括号内任意一个）。括号内用连字符隔开的两个字符表示一个范围；前面带脱字符（“^”）的字符则匹配除这些字符以外的任意字符。问号匹配任意单个字符。比如，想象一个目录里有这么几个文件：

```sh
% ls
abra.cadabra  baby  bozo  core  zippy
% ls *
abra.cadabra  baby  bozo  core  zippy
% ls [ac]*
abra.cadabra  core
% ls b???
baby  bozo
% ls ?o*
bozo  core
```
